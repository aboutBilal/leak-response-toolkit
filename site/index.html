How it works

Before, during and after a leak

  1. 01 · Prevent

    Design leaks out

    Hooks that block .env files and keys, CI scans, keyless deployments, and a grade for every repository.

    leak audit
  2. 02 · Detect

    Find every secret

    Every commit on every branch, including secrets deleted later. Values are always redacted.

    leak scan
  3. 03 · Respond

    Contain the spread

    Rotate in the right order, preserve evidence, and search forks, GitHub, GitLab and web archives for copies.

    leak hunt
  4. 04 · Report

    Close the loop

    A report leadership can act on, message templates, a blameless review and a 45-minute drill.

    leak report

leak audit-org

Every repository, graded on one page

Grade a whole organisation from A to F, worst first, with the exact fix for each gap. HTML for people, markdown and JSON for automation.

  • Tracked secret files, ignore rules, hooks, CI scanning, container hygiene and full history
  • Runs locally or as a scheduled GitHub Action
  • Never prints a secret value

leak hunt · leak report

From evidence to a decision, the same day

Deleting a repository does not delete its copies. leak hunt checks forks, same-name repositories on GitHub and GitLab, the Wayback Machine, Software Heritage and code search, then leak report turns the results into a print-ready report.

  • Every check recorded with its raw response and a checksum manifest
  • Secret types and counts, never values
  • Facts only a person knows are left highlighted to complete

Security of the toolkit

Built to be checked, not just trusted

Signed releases

Archives and container images are signed with Sigstore. Verify one.

SBOM and provenance

Every image ships with a software bill of materials and SLSA build provenance.

OpenSSF Scorecard

An independent security assessment runs on every change. See the report.

Everything pinned

Actions by commit SHA, images by digest, kept current by Dependabot.

Tested on Linux and macOS

shellcheck, actionlint and 34 offline tests on every push; CodeQL on every change to main.

Never touches a secret

No command prints or tests a secret value; tokens stay out of process lists; failed checks are never reported as clean.

Get started

Run it in under a minute

# No local dependencies. Signed image for amd64 and arm64.
docker run --rm -v "$PWD:/repo" ghcr.io/aboutbilal/leak-response-toolkit audit /repo
docker run --rm -v "$PWD:/repo" ghcr.io/aboutbilal/leak-response-toolkit scan /repo
# Needs bash 4.4+, git, curl, jq, and gitleaks or Docker.
git clone https://github.com/aboutBilal/leak-response-toolkit.git
cd leak-response-toolkit && make install
leak doctor
leak audit .
# .github/workflows/secrets.yml
on: [push, pull_request]
permissions:
  contents: read
jobs:
  secrets:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with: { fetch-depth: 0, persist-credentials: false }
      - uses: aboutBilal/leak-response-toolkit@v3.2.0   # pin to a commit SHA in production
        with:
          mode: scan   # scan, audit, audit-org or hunt
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/aboutBilal/leak-response-toolkit
    rev: v3.2.0
    hooks:
      - id: forbid-secret-files   # blocks .env, keys, state files
      - id: leak-guard            # also scans staged changes with gitleaks

Then read the quick start, or rehearse with the 45-minute drill before you need it.
