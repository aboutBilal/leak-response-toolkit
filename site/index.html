If a secret has leaked

The first 15 minutes

  1. 0–2 min

    Say it out loud. Tell your lead or security channel and start a timeline in UTC.

  2. 2–5 min

    Keep the evidence. If the copy is yours and public by mistake, make it private. Don't delete it yet.

    leak snapshot owner/repo
  3. 5–10 min

    Rotate the most powerful secret first. Revoke the old value; adding a new one is not enough.

  4. 10–15 min

    Scan the whole history for every other secret.

    leak scan ./repo
  5. Then

    Remove copies, check the logs, notify.

    leak hunt owner/repo

The leak command

Ten commands for before, during and after a leak. None of them prints a secret value, and any check that cannot run is reported as not checked with exit code 4, never as clean.

Command reference {{ arrow }}

Prevent

leak audit [path]
Grade a repository's secret hygiene from A to F, with the fix for each gap.
leak audit-org <org>
Grade every repository in an organisation on one dashboard, worst first.

Respond

leak snapshot <owner/repo>
Save evidence before the repository is deleted: a mirror, its metadata and a checksum manifest.
leak scan <path>
Find secrets in every commit on every branch, with values redacted. SARIF output for code scanning.
leak forks <owner/repo>
List every fork, including forks of forks, for the takedown request.
leak hunt <owner/repo>
Check GitHub, GitLab, the Wayback Machine, Software Heritage and code search for surviving copies.
leak commits <sha>…
Find public repositories that contain the original commits, even under another name.
leak report <hunt-dir>
Build the leadership report from the evidence.
leak notify <message>
Alert Slack, Microsoft Teams or Discord. The webhook URL never appears in logs.

Security of the toolkit

A tool used in leak investigations has to meet a higher bar. You can check each of these yourself.

Security policy {{ arrow }}
Signed releases
Source archives and container images are signed with Sigstore and ship with an SBOM and SLSA build provenance.
Fails closed
A scanner error or a rate-limited source is reported as not checked, with exit code 4.
Secrets stay private
No command prints or tests a secret value. Tokens and webhook URLs never appear in process lists or logs.
Pinned and tested
Every action and image is pinned by digest. shellcheck, actionlint, CodeQL and 34 tests run on Linux and macOS for every change.
Independently assessed
OpenSSF Scorecard runs on every change. Read the report.

Install

Use the signed container image, install from source, or add it to a pipeline or a commit hook.

Quick start {{ arrow }} 
# No local dependencies. Signed image for amd64 and arm64.
docker run --rm -v "$PWD:/repo" ghcr.io/aboutbilal/leak-response-toolkit audit /repo
docker run --rm -v "$PWD:/repo" ghcr.io/aboutbilal/leak-response-toolkit scan /repo
# Needs bash 4.4+, git, curl, jq, and gitleaks or Docker.
git clone https://github.com/{{ site.repository }}.git
cd leak-response-toolkit && make install
leak doctor
leak audit .
# .github/workflows/secrets.yml
on: [push, pull_request]
permissions:
  contents: read
jobs:
  secrets:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with: { fetch-depth: 0, persist-credentials: false }
      - uses: {{ site.repository }}@v{{ site.version }}   # pin to a commit SHA in production
        with:
          mode: scan   # scan, audit, audit-org or hunt
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/{{ site.repository }}
    rev: v{{ site.version }}
    hooks:
      - id: forbid-secret-files   # blocks .env, keys, state files
      - id: leak-guard            # also scans staged changes with gitleaks

Questions

Does it send my code or secrets anywhere?
scan and audit run entirely on your machine. hunt, forks, commits and audit-org send only repository names, account names and commit IDs to public services. Alerts contain counts and secret types, never values.
Why doesn't it test whether a leaked key still works?
Using a leaked credential is what an attacker does, and it can trigger alarms or break a provider's terms. The answer is the same either way: rotate it.
Does it work outside GitHub?
scan, audit, the hooks and the CI templates work with any Git repository on GitHub, GitLab, Azure DevOps or Bitbucket. hunt searches public GitHub, public GitLab, and web and code archives.
What happens when a service is down or rate-limited?
That check is reported as not checked and the command exits with code 4. A missing answer is never treated as a clean one.
Can my company use and change it?
Yes. It is MIT-licensed. Adapt the runbooks to your organisation and ship the prevention kit in your repository templates.
How do I get help or report a problem?
Ask in Discussions or open an issue. Report vulnerabilities privately, as described in the security policy.
