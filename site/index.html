Security of the toolkit

Built to be verified, not just trusted

A tool used in leak investigations has to meet a higher bar. Every claim below can be checked.

  • Signed releases

    Source archives and container images are signed with Sigstore and ship with an SBOM and SLSA build provenance.

  • OpenSSF Scorecard

    An independent security assessment runs on every change. See the report

  • Fails closed

    A scanner error or a rate-limited source is reported as "not checked" with exit code 4. It is never reported as clean.

  • Secrets stay private

    No command prints or tests a secret value. Tokens and webhook URLs never appear in process lists or logs.

  • Tested on Linux and macOS

    shellcheck, actionlint, CodeQL and 34 offline tests run on every push. Every action and image is pinned by digest.

Get started

Running in under a minute

Use the signed container image, install from source, or add it to your pipeline.

# No local dependencies. Signed image for amd64 and arm64.
docker run --rm -v "$PWD:/repo" ghcr.io/aboutbilal/leak-response-toolkit audit /repo
docker run --rm -v "$PWD:/repo" ghcr.io/aboutbilal/leak-response-toolkit scan /repo
# Needs bash 4.4+, git, curl, jq, and gitleaks or Docker.
git clone https://github.com/{{ site.repository }}.git
cd leak-response-toolkit && make install
leak doctor
leak audit .
# .github/workflows/secrets.yml
on: [push, pull_request]
permissions:
  contents: read
jobs:
  secrets:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with: { fetch-depth: 0, persist-credentials: false }
      - uses: {{ site.repository }}@v{{ site.version }}   # pin to a commit SHA in production
        with:
          mode: scan   # scan, audit, audit-org or hunt
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/{{ site.repository }}
    rev: v{{ site.version }}
    hooks:
      - id: forbid-secret-files   # blocks .env, keys, state files
      - id: leak-guard            # also scans staged changes with gitleaks

Questions

Before you adopt it

Something missing? Ask in Discussions.

Does it send my code or secrets anywhere?

scan and audit run entirely on your machine. hunt, forks, commits and audit-org send only repository names, account names and commit IDs to public services. Alerts contain counts and secret types, never values.

Why doesn't it test whether a leaked key still works?

Using a leaked credential is what an attacker does, and it can trigger alarms or break a provider's terms. The answer is the same either way: rotate it.

Does it work outside GitHub?

scan, audit, the hooks and the CI templates work with any Git repository on GitHub, GitLab, Azure DevOps or Bitbucket. hunt searches public GitHub, public GitLab, and web and code archives.

What happens when a service is down or rate-limited?

That check is reported as "not checked" and the command exits with code 4. A missing answer is never treated as a clean one.

Can my company use and change it?

Yes. It is MIT-licensed. Adapt the runbooks to your organisation and ship the prevention kit in your repository templates.
